02 / TRANSFER LIFECYCLE

受信承諾を、転送の前に。

  1. 匿名セッションを作成

    POST /api/session でID・表示名・秘密トークンを取得。/api/ws に接続し、最初のメッセージで認証します。

  2. 近くの候補を発見

    Geolocationで取得した位置をpresenceとして送信。Hubが座標と精度から候補を判定し、端末IDと表示名を返します。距離や同室を保証する機能ではありません。

  3. 写真を選び、受信を承諾

    まず送るのは名前・形式・サイズなどのメタデータ。受信者がAcceptするとHubがstartを通知し、転送を開始します。

  4. WebRTC接続を確立

    POST /api/ice で接続設定を取得。WebSocketでSDP・ICE候補を交換し、DataChannelを開きます。TURN設定時は短命の資格情報を発行します。

  5. 写真を分割転送・検証

    16 KiBのチャンクと送信バッファ制御で転送。受信側は順序・サイズ・SHA-256を検証し、すべての写真を受信したら完了を通知します。

  6. 端末でプレビュー・保存

    受信したFileをブラウザに一時保持。ユーザー操作でWeb Share APIを呼び、共有シートから保存します。共有APIの成功は写真アプリへの保存確認を意味しません。

03 / DATA BOUNDARIES

写真をサーバーに保存しない。

制御用の短命データは、写真本体とは別に管理します。

BROWSER

写真本体を扱う場所

元のFile、受信チャンク、プレビュー用Object URLを保持。受信完了から10分、破棄、ページ離脱時に原本・プレビュー・JPEGの参照を解放します。端末に保存済みの写真は残ります。

DURABLE OBJECT

接続を再開できる状態

セッション、転送メタデータ、受信者の変換権限、期限付きレート制限をDOストレージに保存。位置・presence等はWebSocket attachmentで保持し、Hibernation後にも利用します。期限切れをalarmで削除します。

IMAGES BINDING

HEICのプレビュー・JPEG変換

利用者の操作で原本をWorkerへ送り、Imagesで変換。公開URLや画像ストレージは使わず、結果はブラウザ内だけに保持します。原本は変更しません。

TURN

通信の中継

直接接続できないときに暗号化通信を中継。アプリは写真をR2・D1・KV・DOストレージに保存しません。管理用秘密トークンはバックエンドに置きます。

05 / DURABLE OBJECTS

複数の端末が、同じ状態を共有する場所。

Durable Objects（DO）は、一意のIDで呼び出せる実行単位に、専用の永続ストレージを組み合わせたCloudflareの仕組みです。pico-dropでは、両端末の状況を把握する「待ち合わせ場所」として使います。

通常のWorkerとDurable Objectの役割
観点 Worker Durable Object
リクエストの行き先 複数の実行インスタンスで処理。毎回同じメモリに届く保証はない 同じ名前空間・IDへの呼び出しは、同じ論理オブジェクトへ届く
状態の管理 インスタンスの変数を、全端末共通の状態としては使えない オブジェクトごとのメモリと、再起動後も残る専用ストレージを持つ
このアプリでの担当 APIの入口、Origin検証、Hubへの転送 接続中の端末、受信承諾、転送状態の調整

同じIDは同じ論理的な窓口を指しますが、同じプロセスが永久に動き続けるわけではありません。概要はCloudflare公式：What are Durable Objects?を参照してください。

pico-dropでは、NearbyHubが両者を仲介する

SENDER → HUB

送信者

request：送りたい写真の情報

RECEIVER → HUB

受信者

accept：受信を承諾

↓ 同じHubに両者の操作を集約 ↓
NEARBY HUB / mvp

受信者が承諾済み

転送状態を更新し、両端末にstartを通知。
その後のSDP・ICE候補も、相手のWebSocketに届けます。

実装では env.HUB.get(env.HUB.idFromName('mvp')) で同じHubを選びます。DOのJavaScriptは単一スレッドで動きますが、非同期処理の待機中には別イベントが進み得ます。このコードは主要な状態更新を blockConcurrencyWhile() で囲み、処理途中への別イベントの割り込みを抑えています。

STORAGE

残す状態を明示する

ctx.storage にセッション、転送メタデータ、レート制限を保存します。保存したデータは通常の変数と違い、オブジェクトがメモリから外れても残ります。このアプリでは期限を付け、alarmで削除します。

HIBERNATION

接続を保って休止する

ctx.acceptWebSocket() で受けた接続は、DOが休止しても維持されます。イベントで復帰するとメモリ内の変数は再初期化されるため、接続ごとの情報は serializeAttachment() で保持し、復帰時に読み出します。

ALARM

期限切れを片付ける

現在は接続や保存データが残っている間、約15秒ごとにalarmを予約。期限切れセッション・転送を整理し、古い位置情報を候補から除きます。alarmやメッセージで復帰するため、更新頻度は実行量にも影響します。

Hibernation中は実行時間に対する課金が発生しません。リクエストやストレージなどの料金とは別の扱いです。attachmentは接続に紐づく情報であり、切断後の再接続や転送の途中再開を保証するものではありません。Cloudflare公式：WebSocket Hibernation

規模が増えたときの設計

現在は全端末を1つのHubに集め、アプリ側でWebSocketを最大200接続に制限しています。DO全体の製品上限を示す数字ではありません。利用が増えたらエリアや部屋ごとに別IDのHubへ分ける設計が必要です。その際は、隣接エリアの候補探索や移動時の所属変更も設計します。写真本体は引き続きDataChannelで転送します。
